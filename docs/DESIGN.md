# DESIGN: Juan Miguel, signal path

## Brief

**Subject:** Juan Miguel, computer engineer and technology consultant in Madrid.
**Audience:** Potential clients, technical leads and peers who need to judge whether he can
understand a system and carry a decision through implementation.
**Job:** Make the value legible in the first frame, give proof through two real engineering
projects, and open a direct conversation.
**Language:** Spanish. The repository, the existing content and the location are Spanish; the
owner wrote the request in English. Every visible string stays in Spanish.
**Assets:** `apps/web/src/assets/profile.webp` (owner supplied), the repository itself.
**Constraints:** Keep the Astro + pnpm + Turborepo + TypeScript monorepo, the content
collections, the component package split, the deployment workflow and the security checks
already present. Keep everything on one page: discipline (method and capabilities), work,
experience, profile and contact. Technology marks use Tabler for interface icons and Simple
Icons for marks.

## Concept

```text
Idea:        The portfolio is a signal path. One trace connects profile, work,
             experience and contact like nodes in the same system.
Metaphor:    A circuit schematic: a bus, branches, ports and a pulse.
Signature:   A scroll-driven trace in the page margin. It draws as the visitor
             moves, branches into every section node, and carries a pulse that
             keeps breathing when the page is still.
Emotion:     Calm precision. The sense of a person who can see the whole system
             and knows where the signal goes.
Motion verb: Route. Signals travel, branch and lock at a node.
Screenshot:  Giant stepped name, a red node beside it, a hairline trace entering
             from the margin, and mono coordinates in the corners.
```

The concept survives the whole site: section labels are nodes, project rows are ports, the
dark contact field is the endpoint and the navigation is the map of the same path. Everything
runs on one page, so the trace never restarts.

### Three concepts considered

| | A. Signal path | B. Technical datasheet | C. Noise becomes signal |
|---|---|---|---|
| Territory | Material of the profession | Formal system | Process metaphor |
| One sentence | The site is one circuit connecting the person's work. | The site is a specification sheet for a person. | The site starts as noise and resolves into legible work. |
| Signature | Scroll-driven bus with a live pulse and branches | Annotation pen completes the sheet | A field of static resolves as you scroll |
| Risk | Could become decorative circuitry | Likely a layout, not a behaviour | Generic tech trope, shader-heavy and expensive |
| Scores (O/F/Fe/P) | 4 / 5 / 5 / 2 | 3 / 3 / 5 / 4 | 4 / 3 / 3 / 3 |

**Pick A.** It is generated by the actual work, it gives the site a behaviour rather than a
skin, and it is cheap enough to execute precisely without WebGL. The technical-datasheet
restraint survives as a detail: indices, coordinates, rulers and tabular figures.

## Art direction

### Palette

| Role | Value | Use |
|---|---|---|
| Ground | `#F2F1EC` | Paper. The whole site except the closing field. |
| Ink | `#141413` | Text, rulers, the closing field. |
| Muted | `#62615B` | Secondary text (5.49:1 on ground). |
| Line | `rgb(20 20 19 / 14%)` | Hairlines, grid, inactive trace. |
| Accent | `#D93A2B` | The signal: nodes, live trace, large type, focus. |
| Field | `#141413` | The closing contact/footer field and the menu. |

Small accent text uses `#B72C20` on paper (5.47:1); on ink uses `#FF7A6B` (7.24:1).
`#D93A2B` is reserved for graphics and large text, where the 3:1 large-text threshold applies.

No gradient identity, no glass, no soft shadows, no rounded pills.

### Dark theme

Dark appearance is available through `html[data-theme="dark"]`, set by:

- `ThemeScript`, a blocking inline script in `<head>`, or
- `ThemeToggle`, the button in the header, through a deferred module.

`tokens.css` overrides palette, border, muted text and field colours for dark mode. The toggle
updates `data-theme`, `color-scheme` and `meta[name="theme-color"]`; the script writes the
values to `data-theme-light`, `data-theme-dark` and `data-theme-storage-key` on `<html>`. The
two pieces are intentionally separate: the script must run before first paint; the toggle
should not be required for bootstrapping.

### Type

- **Display and text:** Switzer, self-hosted. A neutral Swiss grotesk with a tighter, more
  contemporary voice than Inter.
- **Data:** JetBrains Mono 400/500, used only for indices, coordinates, status, years and
  technology names. Not every label.
- Body 16 to 18 px, 1.55 leading, measure 38 to 62 characters.
- Display tracking -0.045em, leading 0.84 to 0.9. The name is composed as two stepped lines,
  not a centered hero.
- Numbers use tabular figures. Real quotes and Spanish accents are kept.

### Grid and rhythm

- 12 columns, shell `min(100% - 2 * gutter, 92rem)`, gutter `clamp(1rem, 3vw, 2.5rem)`.
- Strong left edge: node labels in column 1, content from column 4 or 5, metadata in columns
  10 to 12. The trace runs in the outer margin, just left of the shell.
- Section rhythm is deliberately varied: full-viewport hero, airy work index, tight capability
  table, medium experience block, airy profile, full-bleed dark contact.
- One radius rule: 0. One shadow rule: none. One border rule: 1 px.

### Motion language

- One clock: GSAP ticker drives Lenis, ScrollTrigger and the trace.
- `expo.out` for entrances, `expo.inOut` for overlays, `power3.out` for hover feedback.
- Hover feedback 250 to 350 ms. Text reveals 0.9 to 1.2 s, stagger 0.04 to 0.08 s.
- Loader: 0.6 s floor on touch and 0.8 s on desktop, cap at 1.5 s, about 2.4 s including exit.
  It exits into the hero.
- Primary targets answer in the motion verb: project rows invert and a branch reaches them;
  buttons flood from the left; arrows travel; nav uses an underline draw. Utility links may
  only change colour.
- The trace has an idle state: the pulse at the current scroll position breathes slowly. It
  pauses off screen and is static under reduced motion.
- Under reduced motion: no Lenis, no reveals, no loader theatrics, no pulse, and contact opens
  without transition. The trace is drawn complete and all content is visible.

### Genericness test

The reflex answer to “Swiss minimal portfolio for an engineer” is a centered hero, a neon
accent on near-black, three rounded feature cards, an uppercase eyebrow above every section
and a grid of fake dashboards. This site deliberately rejects all five. The Swiss restraint
comes from the grid, the type and one red signal, not from a template. Numbered labels are not
decoration: they are node positions and help orientation. Project visuals are rows and
metadata, not invented screenshots.

## Content rules

- Spanish, sentence case, no em or en dashes in visible text.
- Specific verbs and nouns. Avoid filler such as “elevate”, “seamless”, “passionate”,
  “cutting-edge”.
- No invented clients, logos, awards or metrics.
- Each published page and shared metadata carry unique titles, descriptions and OG data.

## Technical decisions

- Keep the monorepo: `apps/web`, `packages/brand`, `packages/ui`, with `apps/web` as the
  deployable site.
- Keep Astro content collections and Zod validation. Add page fields and project metadata to
  existing schemas instead of moving content into components.
- Use GSAP, Lenis and the engine lifecycle under `apps/web/src/engine`. The adapter is Astro;
  there is no client-side route switcher.
- One page carries profile, approach, work, capabilities, experience and contact. The footer is
  the dark contact field and legal bar; it is mounted outside `main`.
- Project rows are native links. There are no project sheets and no separate project routes.
- Icons: Tabler for interface and Astro icon loader, Simple Icons for technology marks. Only
  used icons ship.
- Self-host Switzer and JetBrains Mono. Preload only the first two fonts used above the fold.
- One committed light theme plus a dark theme override, controlled by `ThemeScript` and
  `ThemeToggle`. Defaults live in `packages/ui/src/theme.ts`.
- Shared classes use prefixes `base-hero`, `base-footer`, `base-wrapper`, `base-section-head`,
  `base-btn`.
- No custom brand cursor; it was removed entirely (it was never initialised). Do not reintroduce
  it without real use.
- `initMagnetic` was removed for the same reason (`data-magnetic` was unused).
- Loader became its own component (`Loader.astro`) instead of inline markup in the layout.
- Content is loaded once through `apps/web/src/lib/site.ts`.
- Portraits use responsive `srcset` widths, so a 1x screen does not download the largest file.
- TypeScript config uses `astro/tsconfigs/strictest` directly for `web` and `ui`; `brand` keeps a
  minimal autonomous `tsconfig.json`. The old `packages/typescript-config` was removed for
  contributing nothing.
- Security checks are part of the workflow: `security.txt`, gitleaks, provenance, and
  accessibility tests. Keep the deployment workflow and provenance checks; the site is also the
  proof of the second project.
- Package state:
  - `@juan-miii/brand`: public (`1.0.0`), CSS only.
  - `@portfolio/ui`: private, `1.0.0`, versioned by Changesets without tags.
  - `@portfolio/web`: private, `2.0.0`, versioned by Changesets without tags.
  - root `portfolio`: `2.0.0`, infrastructure only.

## Accessibility and performance

- Single `<h1>` per page, ordered headings, landmarks, `lang`, real links and buttons.
- Skip link, visible focus, AA contrast on secondary text and shared dark modes.
- `main` has no `tabindex` override.
- Loader has a timeout fallback and all motion stops under `prefers-reduced-motion`.
- Mobile layout is composed for small widths; tap targets and overflow tests pass.
- Images and fonts use responsive/loading strategies; CSS is inlined by Astro.

## Content and operations

- Spanish, sentence case, no em or en dashes in visible text.
- Specific nouns and numbers only when true. No invented clients, logos, awards or metrics.
- Content lives in `apps/web/src/content`, schemas in `content/schemas`, map in `COMPONENTS.md`.
- Shared content passes `pnpm test`, `pnpm check`, `pnpm build`, `pnpm test:e2e` and
  `pnpm test:a11y` locally.
- Security changes require keeping `security.txt`, gitleaks and provenance aligned.
